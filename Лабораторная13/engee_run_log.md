# Журнал выполнения ЛР 13 (Engee)

Среда: процессор (5 ядер, 16 ГБ), Python 3.11 из `/user/.user_venvs/py3.11`, PyTorch 2.4.1, `pytorch-fid` 0.3.0 (Inception, блок pool3, 2048 признаков); графического ускорителя нет. Подготовка начата 20.09.2026 в Engee 26.8.2-H3, расчёт завершён 08.10.2026 в Engee 26.9.2-H4 (версии Python, PyTorch и `pytorch-fid` не менялись).

## Что запускалось

1. Подготовка по наборам (`run13.py prep <набор>`): обучение двух GAN на 3000 шагов (базовая с сохранением образцов на шагах 300, 700, 1500, 3000 и GAN с сильным дискриминатором, seed 101) → `gen13_<набор>.npz`; затем признаки Inception для 10 пулов (реальные обучающие и тестовые, сгенерированные, часть — при `nearest`) → `feat13_<набор>.npz`. Скорость извлечения признаков — около 8 изображений в секунду при четырёх потоках, около 28 минут на набор.
2. Расчёт 30 вариантов (`run13.py calc <набор>`): для каждого варианта режимы A и B × 5 подвыборок (seed 101…105) → `res13_c<набор>.jsonl`, строка на вариант. Один вариант — 125–175 с.
3. Сводка `summarize13.py` → `summary13.txt` (сохранена как `res13_summary.txt`).
4. Демонстрация (`demo13.py`, набор 1 «диск», 378 с) → `demo13_fmt.txt` (SHA-256 `68cf0f53…`) и лист образцов `demo13_ckpt.png` (перенесён снимком экрана в натуральную величину, 768×240).

## Что пошло не так и как исправлено

- Сеанс Engee 08.10 останавливался несколько раз; фоновые процессы при этом терялись. `extract()` в `lab13_lib.py` сделан возобновляемым: признаки каждого пула сохраняются отдельным файлом `part13_<набор>_<пул>.npy`, при перезапуске готовые пулы не пересчитываются (исходная версия — `lab13_lib_orig.py`). `run13.py calc` с самого начала пропускал готовые варианты.
- Первый план (два процесса по наборам (0, 2, 4) и (1, 3) одновременно с досчётом ЛР 12) перегружал среду; дальше расчёт шёл одной цепочкой (наборы 0–4 по порядку, четыре потока), а генераторы и признаки набора 5 считались вторым процессом с двумя потоками, когда ЛР 12 уже была завершена.
- Время расчёта FID (`seconds`) получено при разной загрузке процессора (один или два процесса), поэтому оно сопоставимо только внутри пары A–B одного варианта.

## Ограничения

Признаки получены для синтетических сцен 32×32, растянутых до 299×299; сеть Inception обучена на фотографиях ImageNet, поэтому абсолютные значения FID несопоставимы с опубликованными. Для каждого набора обучено по одной модели каждого вида (seed 101): разброс в таблицах отражает только выбор подвыборки. Числа таблиц в МУ совпадают с `res13_summary.txt`.
